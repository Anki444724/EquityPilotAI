# Next-200 candidate derivation — design + status (2026-08-23, revised 2026-08-24)

Investigation + tooling only. **No production data was imported or
backfilled.** The production database was never written to — the CLI is
read-only against it (SELECT-only), and the derivation runs in memory.

## 0. Design revision (2026-08-24)

Production invalidated the original candidate source. The database already
contains the full BSE active master — **7,042 companies (500 NIFTY500 +
6,542 non-NIFTY500), and all 4,976 BSE ISINs are present in
`companies`** — so "BSE master minus database" yields **zero** candidates.
The candidate pool is therefore the database itself:

| Step | Revised design |
|---|---|
| Candidates | `companies` rows that are **not NIFTY500** (`index_membership` tag, cross-checked against today's NSE Nifty 500 list so a stale tag cannot leak a live constituent in), **active**, and **Indian** (INE ISIN, or no ISIN with INR currency). |
| Market cap | Tier 0: the BSE master's own `Mktcap`, matched to candidates **by ISIN**, unit-calibrated (RELIANCE reference; rupees vs crore, refused rather than guessed). Secondary sources (FMP screener, screener.in, FMP profile) fill **only** the companies BSE does not match. |
| Report | A `coverage` block in the JSON: `total_companies_in_db`, `excluded_nifty500_tag`, `excluded_nifty500_live_list`, `excluded_not_active`, `excluded_non_indian`, `total_candidates`, `bse_mktcap_matched`, `bse_mktcap_unit`, `secondary_matched`, `missing_market_cap`, `ranked`, `rank_range` (501–700), top/bottom market cap, and the per-row `mcap_source`. Rows carry `company_id` so the reviewed report maps straight onto the rows a later backfill would ingest. |
| Backfill gate | **The final DB backfill is a separate, explicit step and is NOT run by this script.** Nothing is backfilled until the dry-run coverage report is reviewed. |

Modes: `--report-only` (classification/coverage only — no BSE master, no
market-cap fetch of any kind) and the full dry run (BSE Mktcap + gap-fill +
ranks 501–700). `--no-nifty500-check` disables the live-list cross-check
(tag-based exclusion still applies).

## 1. Method

| Step | Source | Notes |
|---|---|---|
| Candidate universe | BSE active-scrip master (`ListofScripData`, segment=Equity, status=Active) | Same exchange endpoint the Nifty 500 importer already calls in production (same URL + Referer). Covers dual-listed and BSE-only listings; carries ISIN + name + ticker per scrip. |
| Exclusion | `companies` table (every existing record — the 525) | ISIN first, then uppercase ticker. ISIN is the security's legal identifier; a ticker-only hit is still excluded but labelled in the report so the reasoning is visible. US/foreign ISINs and no-ISIN rows are surfaced, not silently dropped. |
| Market cap | Tiered: **(0)** the BSE master's own `Mktcap` field (the exchange reporting its own companies — free, already fetched; unit auto-calibrated, see §2); then gap-fillers: **(a)** FMP screener (bulk, plan permitting); **(b)** screener.in per candidate (the platform's primary financial source, throttled ~1.1 s); **(c)** FMP per-symbol profile (last resort, budget-aware) | See §2 for the source decision. |
| Ranking | market cap, descending, top 200 | Proposed ranks 501–700. Ties break by name (stable output). Candidates without a figure are counted in the summary, never ranked at zero. |

## 2. Authoritative market-cap source — decision

**The BSE master's own `Mktcap` field is the primary source** — the
listing exchange reporting the market cap of its own companies, already in
hand from step 1, so it costs zero extra calls and is the most authoritative
figure available. One caveat: BSE does not document the unit of `Mktcap`
(rupees vs crore). The parser therefore **calibrates** against RELIANCE —
the market leader, whose mcap sits between 5e13 and 5e15 rupees for any
plausible date, far from the boundary between the two candidate units
(>1e12 ⇒ rupees; ≤1e9 ⇒ crore; in between ⇒ the tier is skipped rather
than guessed). The report's `mcap_source` column shows which source each
figure came from.

Gap-fillers, in the platform's own source order, for scrips the master's
`Mktcap` does not cover:

- **FMP screener** — `/stable/stock-screener?exchanges=nsi|bse`, one
  paginated call for the whole Indian listed set with `marketCap` (plan
  permitting; a free-plan 402/403 is detected and the run falls through).
- **screener.in per candidate** — the platform's primary financial source
  (proven in production, IP-throttled ~1.1 s; only *gaps* are fetched, so
  a full first run is far shorter than 4,400 calls; resumable).
- **FMP per-symbol profile** — last resort, budget-aware
  (`--max-fmp-profile`).

FMP remains the cross-check: it is the platform's primary market-data
provider (`FMP_API_KEY` provisioned in production; `app/data/providers/fmp.py`
parses `marketCap`), so any figure the platform shows after ingestion
matches the report's `fmp_*` entries.

Considered and rejected as the primary: NSE (publishes no constituent list
beyond the Nifty 500 — verified `ind_niftymicrocap150list.csv` does not
exist); NSE bhavcopy (OHLCV only, no market cap).

## 3. What is implemented

| File | What |
|---|---|
| `backend/app/services/universe/next200.py` | Pure derivation service: BSE-master parsing, ISIN/ticker exclusion, ranking, CSV/JSON rendering. No network or DB inside. |
| `deploy/derive_next_200.py` | CLI wiring: fetches BSE master, reads the DB **read-only**, tiers the market-cap sources, writes `next200_candidates_<date>.csv` / `.json`. `--report-only` runs exclusion without any market-cap fetch. |
| `backend/tests/test_derive_next200.py` | 45 unit tests: parser against the actual production BSE payload (`Scrip_Name`, `scrip_id`, `Mktcap`, mixed-case fields) plus legacy all-caps fallback, Mktcap unit calibration (rupee/crore/ambiguous), the BSE Mktcap map, the database-driven candidate filter (NIFTY500 tag, live-list cross-check, not-active, non-Indian), DB ranking with company_id/exchange/bse_code, rank 501–700 assignment, counts, report shape. |

Both network-dependent steps reuse sources the platform already runs in
production (BSE master via the importer's proven endpoint+Referer;
screener.in via the production fetcher). The CLI was smoke-tested
end-to-end against a stand-in database with a stubbed BSE master and
market-cap feed: exclusions, ranks 501+, CSV/JSON output all correct, zero
DB writes.

## 4. Run on AWS (when approved)

The container's `/app` is read-only, so the report must go to a writable —
preferably host-mounted — path. The CLI resolves the output directory in
this order: explicit `--out` (an unwritable explicit path is a hard error),
`$UNIVERSE_REPORT_DIR`, `./universe_725_investigation` under the working
directory, then `/tmp/universe_725_investigation`. It also **fails fast** on
an unwritable path — before the BSE fetch and the market-cap sweep, not
after. On the AWS compose deployment `/app/backups` is a host-mounted
volume, so that is the safe durable destination.

```bash
# on the AWS box, with the production DATABASE_URL (read-only access is
# sufficient — the CLI issues SELECTs only):

export DATABASE_URL="postgresql+psycopg://..."
export UNIVERSE_REPORT_DIR=/app/backups/universe_725_investigation
# (or pass --out /app/backups/universe_725_investigation on each command)
# FMP_API_KEY is optional — tier 0 (BSE's own Mktcap) needs no key;
# FMP only fills gaps the master's figure leaves.

# 1) exclusion report only — no market-cap calls at all:
python3 deploy/derive_next_200.py --report-only

# 2) full report (BSE Mktcap first; FMP/screener.in fill gaps):
python3 deploy/derive_next_200.py --limit 200
#    -> $UNIVERSE_REPORT_DIR/next200_candidates_<date>.csv / .json
```

Output columns (exactly the requested report): `proposed_rank`, `ticker`,
`company_name`, `isin`, `exchange`, `market_cap_inr_crore`, `mcap_source`,
`current_universe_status`, `bse_scrip_code`, `sector`.

## 5. Honest caveat from this environment

This sandbox cannot reach BSE's API (it requires the `Referer` header the
fetch tool cannot send, and direct TLS to bseindia.com is blocked here) nor
FMP/screener.in (no production key here). So the final top-200 *with live
figures* is produced by the command above on AWS — one read-only run. What
is verified here: the full derivation logic (45 unit tests, including the
parser against the **actual production payload format** — `SCRIP_CD`,
`Scrip_Name`, `Status`, `Segment`, `ISIN_NUMBER`, `INDUSTRY`, `scrip_id`,
`Mktcap` — which was pinned after the first AWS run reported 0 scrips
because the parser only knew the older all-caps field names), the
Mktcap unit calibration, and the CLI wiring (end-to-end smoke test with
stand-ins).

The first AWS run hit two issues, both now fixed in this revision:
1. **0 active equity scrips** — the live BSE payload uses `Scrip_Name`
   (not `COMP_NAME`) and `scrip_id` for the ticker; the parser was
   updated to read the current names first with the old names as
   fallback.
2. **Unwritable output path** — the default sat under the container's
   read-only `/app`; the output directory is now configurable
   (`--out` / `$UNIVERSE_REPORT_DIR`) with a safe fallback and a fail-fast
   writability check.
