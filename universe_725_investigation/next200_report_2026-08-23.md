# Next-200 candidate derivation — design + status (2026-08-23)

Investigation + tooling only. **No production data was imported or
backfilled.** The production database was never written to — the CLI is
read-only against it (SELECT-only), and the derivation runs in memory.

## 1. Method

| Step | Source | Notes |
|---|---|---|
| Candidate universe | BSE active-scrip master (`ListofScripData`, segment=Equity, status=Active) | Same exchange endpoint the Nifty 500 importer already calls in production (same URL + Referer). Covers dual-listed and BSE-only listings; carries ISIN + name per scrip. |
| Exclusion | `companies` table (every existing record — the 525) | ISIN first, then uppercase ticker. ISIN is the security's legal identifier; a ticker-only hit is still excluded but labelled in the report so the reasoning is visible. US/foreign ISINs and no-ISIN rows are surfaced, not silently dropped. |
| Market cap | Platform's own market-data sources, in order: **(a)** FMP screener (bulk listing of all NSE/BSE stocks with `marketCap` in one paginated call, when the key's plan allows); **(b)** screener.in per candidate (the platform's primary financial source — `app.data.screener_source` already parses `market_cap` per company in production, throttled ~1.1 s); **(c)** FMP per-symbol profile (last resort, budget-aware) | See §2 for the source decision. |
| Ranking | market cap, descending, top 200 | Proposed ranks 501–700. Ties break by name (stable output). Candidates without a figure are counted in the summary, never ranked at zero. |

## 2. Authoritative market-cap source — decision

**FMP (Financial Modeling Prep)** is the identified authoritative source,
because it is *already the platform's primary market-data provider*
(`FMP_API_KEY` is provisioned in production; `app/data/providers/fmp.py`
parses `marketCap` from its profile/quote payloads, and the production
router already reports it). Using the same source keeps the candidate
report's figures identical to what the platform shows after ingestion.

- Bulk: `/stable/stock-screener?exchanges=nsi|bse` — one paginated call for
  the whole Indian listed set with `marketCap` per stock (plan permitting;
  a free-plan 402/403 is detected and the run falls through, not failed).
- Fallback: the platform's existing per-company sources — screener.in
  (proven in production, IP-throttled; a first full run over ~4,400
  candidates takes roughly an hour and is resumable) and FMP
  `/stable/profile` per symbol.

Considered and rejected for the bulk step: NSE (publishes no constituent
list beyond the Nifty 500 — verified `ind_niftymicrocap150list.csv` does
not exist); BSE scrip master (authoritative for the universe and ISINs, but
carries no market-cap field); NSE bhavcopy (OHLCV only, no market cap).

## 3. What is implemented

| File | What |
|---|---|
| `backend/app/services/universe/next200.py` | Pure derivation service: BSE-master parsing, ISIN/ticker exclusion, ranking, CSV/JSON rendering. No network or DB inside. |
| `deploy/derive_next_200.py` | CLI wiring: fetches BSE master, reads the DB **read-only**, tiers the market-cap sources, writes `next200_candidates_<date>.csv` / `.json`. `--report-only` runs exclusion without any market-cap fetch. |
| `backend/tests/test_derive_next200.py` | 16 unit tests: exclusion (ISIN-first, ticker fallback, US scope, no-ISIN surfacing), ranking order, rank 501–700 assignment, tie-break, counts, report shape. |

Both network-dependent steps reuse sources the platform already runs in
production (BSE master via the importer's proven endpoint+Referer;
screener.in via the production fetcher). The CLI was smoke-tested
end-to-end against a stand-in database with a stubbed BSE master and
market-cap feed: exclusions, ranks 501+, CSV/JSON output all correct, zero
DB writes.

## 4. Run on AWS (when approved)

```bash
# on the AWS box, with the production DATABASE_URL (read-only access is
# sufficient — the CLI issues SELECTs only):

export DATABASE_URL="postgresql+psycopg://..."

# 1) exclusion report only — no market-cap calls at all:
python3 deploy/derive_next_200.py --report-only

# 2) full report (bulk FMP first if the plan allows; screener.in otherwise):
python3 deploy/derive_next_200.py --limit 200
#    -> universe_725_investigation/next200_candidates_<date>.csv / .json
```

Output columns (exactly the requested report): `proposed_rank`, `ticker`,
`company_name`, `isin`, `exchange`, `market_cap_inr_crore`, `mcap_source`,
`current_universe_status`, `bse_scrip_code`, `sector`.

## 5. Honest caveat from this environment

This sandbox cannot reach BSE's API (it requires the `Referer` header the
fetch tool cannot send, and direct TLS to bseindia.com is blocked here) nor
FMP/screener.in (no production key here). So the final top-200 *with live
figures* is produced by the command above on AWS — one read-only run. What
is verified here: the full derivation logic (16 unit tests), the CLI wiring
(end-to-end smoke test with stand-ins), and the source/endpoint decisions
(each cross-checked against the code that already calls them in
production).
